# 订单排产与设备异常智能体系统 — 归档说明

> 本文档是对 `order-scheduling-agent` MVP 项目的整理归档说明，梳理工程架构、Agent 框架、知识库、人工确认/审核点、权限体系五个核心维度，便于快速理解项目全貌与关键安全机制。

---

## 一、项目概览

一个基于 **FastAPI（异步）+ SQLite + 单页 HTML** 的完整可演示 MVP：员工用自然语言发起排产建议 → 检索制度知识库 → 生成草稿（人工确认）→ 管理员审批 → 生效为当日计划，全程审计留痕。支持接入通义千问、DeepSeek 等国产大模型，未配置密钥时自动进入本地 Mock 演示模式。

**核心技术栈**：FastAPI、Uvicorn、aiosqlite、httpx、PyJWT、Jinja2、python-multipart、pypdf。

**代码规模**：`app/` 下 20 个模块、约 3800 行；7 张 SQLite 数据表；25 项单元测试。

## 三、Agent 框架

### 3.1 执行循环（agent_loop.py）

受约束的智能体执行循环，核心是**模型决策 → 工具执行 → 结果回填 → 再决策**的迭代，最多 8 轮：

```
意图路由（agent_orchestrator）
   ↓
决策引擎（RuleDecisionEngine / LLMDecisionEngine）
   ↓ 输出决策（tool / final / confirm 三类）
工具执行（白名单校验）
   ↓ 结果回填
再决策 … 直到完成或挂起
```

### 3.2 决策引擎双实现

- **RuleDecisionEngine**：本地规则决策，无需模型，确定性输出。
- **LLMDecisionEngine**：真实大模型做工具决策（OpenAI 兼容 JSON 结构化输出），失败自动回退规则引擎。由 `_make_decision_engine` 工厂按环境变量 `LLM_DECIDE` 选择。

### 3.3 工具 / Skill 白名单（agent_tools.py）

模型只能从当前 Skill 的 `allowed_tools` 里选工具；审批、生效、设备控制等**不在工具清单**中，模型无法调用。三个 Skill：

| Skill | 用途 |
|---|---|
| policy_qa | 制度问答（检索制度条文） |
| schedule_change | 排产变更（快照/校验/草稿/仿真/提交） |
| equipment_exception | 设备异常（登记/影响分析） |

### 3.4 状态机与凭证链

状态机：`SNAPSHOT_READY → INPUT_VALIDATED → DRAFTED → SIMULATED → OUTPUT_VALIDATED → PENDING_APPROVAL → APPROVED → ACTIVE`。凭证链（snapshot_id / validation_id / draft_id / simulation_id / result_validation_id）单次使用、哈希绑定、过期失效，杜绝伪造凭证绕过校验。

### 3.5 五层安全护栏

1. 模型无审批权、无生效权、无设备控制权（工具白名单外）
2. 凭证链单次使用，状态机校验，无法伪造
3. 建草稿前强制人工确认（控制流硬约束，不依赖模型自觉）
4. 越权工具调用被拒绝并触发回退
5. 工具护栏异常优雅降级为 FAILED，不导致崩溃

## 四、知识库

### 4.1 知识库内容（knowledge_base/）

| 文档 | 关键制度内容 |
|---|---|
| 排产规则.md | 排产优先级（准时交付率第一、换型次数第二、设备利用率第三）、插单处理、缺料处理、交期变更 |
| 审批流程.md | 排产发布由计划员申请、质量主管审核、厂长批准 |
| 设备异常处理制度.md | 设备异常停机登记、原因记录 |

### 4.2 检索机制（retrieval.py + kb_store.py）

- **离线向量化**：字符 unigram + bigram 混合加权哈希到 512 维向量（FNV-1a 稳定哈希，跨进程确定一致）。
- **相似度检索**：余弦相似度 + 关键词重叠兜底（连续 2 字重叠 ≥ 2 即召回），双键排序。
- **加载机制**：启动时 `load_documents()` 从数据库加载切片向量到内存，上传/删除后刷新缓存即时生效。
- **可扩展**：接口不变，后续可替换为向量检索。

## 五、人工确认 / 审核点（共 4 处）

系统在关键环节设置人工介入点，智能体无法自行跨越：

| # | 审核点 | 位置 | 说明 |
|---|---|---|---|
| 1 | **建草稿前人工确认** | agent_loop.py `confirm()` / `AWAITING_CONFIRMATION` | 员工发起排产变更，智能体生成草稿预览后**挂起等待员工明确确认**，确认后才真正建草稿；拒绝则取消。这是控制流硬约束，即使模型想直接建草稿也会被循环层强制拦截 |
| 2 | **管理员审批** | routes_agent.py `approve` / `reject` | 草稿提交后进入 `PENDING_APPROVAL` 待审批状态，由管理员在后台「排产审批」页同意或拒绝；同意才自动生成「当日计划」生效版本 |
| 3 | **对话审计标记** | routes_admin.py `flag_conversation` | 管理员在「对话审计」页对会话做"疑似违规"标记/取消（含备注），写入 audit_logs 追加式留痕 |
| 4 | **确认令牌校验** | agent_loop.py `confirm()` 中 FORBIDDEN | 员工确认时校验 pending_token 归属，防止确认他人草稿请求 |

> 设计原则：**审批权、生效权、审计权均不属于模型**，模型只能"请求确认""提交审批"，最终裁决由人完成。

## 六、权限体系（2 角色 + 接口级强制）

### 6.1 双角色

| 角色 | 标识 | 访问范围 |
|---|---|---|
| 员工 | employee | 问答页 `/`、发起排产建议、确认草稿 |
| 管理员 | admin | 管理后台 `/admin`（审批、知识库、提示词、审计、当日计划） |

### 6.2 接口级权限强制

- `login_required`：登录即可访问（问答、确认草稿等）。
- `admin_required`：仅管理员可访问，非管理员返回 `40302 无权限执行此操作`。
- 管理后台路由 `routes_admin.py` 整个 `APIRouter` 以 `dependencies=[Depends(admin_required)]` 挂载，全部接口管理员专属；员工访问后台页面被重定向到问答页。
- JWT 双通道：接口走 Bearer 头，页面走 HttpOnly Cookie。

## 七、运行方式

```bash
cd order-scheduling-agent
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt
uvicorn app.main:app --host 127.0.0.1 --port 5000
```

浏览器访问 `http://localhost:5000`。演示账号：`employee / 123456`（员工）、`admin / 123456`（管理员）。

> 说明：本归档为**纯净源码**，不包含任何运行产物（无 `__pycache__`、无 `data/` 数据库、无 `output/` 文档流水线产物）。首次启动时系统会自动完成：创建 `data/` 目录 → 建库建表 → 写入预置账号 → 导入知识库示例制度 → 加载检索向量缓存，无需人工预置任何目录或文件。

大模型配置（环境变量）：`LLM_API_KEY`、`LLM_BASE_URL`（默认通义千问）、`LLM_MODEL`（默认 qwen-plus）、`LLM_MOCK`、`LLM_DECIDE`。详见 `app/config.py` 与 `README.md`。
